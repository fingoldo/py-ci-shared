# Dispositions t1: gate teeth and canary corpus

### INFRA-2
**Disposition:** RESOLVED -- tests/test_gate_teeth.py runs 53 corpus-scanning gates through their public `assert_*` entries over the canary corpus: the violation must fail naming the seed, the clean control must pass, the BOM copy must be reported exactly as the plain violation, an unparsable file must fail the gate (by name unless it replaces the single file passed), and an empty corpus must fail (floor). A static teeth-check per gate asserts that violation != clean, that bom == BOM + violation byte for byte, that violation and clean parse, and that the unparsable file really does not parse. A meta-test requires every registered gate/library module, and every unregistered public module, to have a canary or a reasoned EXEMPT entry. Confirmed gate defects are strict xfails (listed below); regression test: tests/test_gate_teeth.py

### INFRA-3
**Disposition:** RESOLVED -- tests/canary/<gate>/{violation,clean,bom,unparsable,support}/ holds a few-line mini-repo per gate (53 gates). Files carry a `.canary` suffix, so pytest and this repo's own gates neither collect nor scan them. The test copies each variant into tmp_path and strips the suffix, so the repo is never written. Non-Python scanners (workflow YAML, pyproject TOML, SQL, Markdown) are included where the gate takes a path.

## Gate defects found

Each item is a strict xfail in tests/test_gate_teeth.py. None was fixed here.

1. **env_flag_parsing: a BOM file is skipped.** Input: `﻿import os\nif os.environ.get("SEED_FLAG"): pass`. Observed: `assert_env_flags_use_one_parser` passes. Expected: the finding. Cause: `find_hand_parsed_env_flags` reads with `encoding="utf-8"`, not `read_source`.
2. **env_flag_parsing: an unparsable file is skipped.** Input: a clean file plus `broken.py` (`def broken(:`). Observed: pass. Expected: failure naming broken.py. Cause: `except (SyntaxError, UnicodeDecodeError): continue`.
3. **git_dependency_pins: an unparsable pyproject passes.** Input: `[project\nname = "seed\n`. Observed: pass. Expected: failure. Cause: `_source_table_violations` swallows the TOML `ValueError` and returns `[]`, and the line regex finds nothing.
4. **git_dependency_pins: a single-line dependency array is not scanned** (documented here only; the canary uses the multi-line form). Input: `dependencies = ["seedlib @ git+https://github.com/o/seedlib.git@main"]`. Observed: `find_unpinned_git_dependencies` returns `[]`. Expected: `["main"]`. Cause: `_GIT_DEP_RE` is anchored at line start (`^\s*["']?name @`).
5. **No floor on an empty corpus.** Each of these entries passes on an empty directory, so a scan that lost its subject stays green:
   - `module_reload_safety.assert_no_reloads_in_code`
   - `vacuous_loop_assertions.assert_no_new_floorless_loop`
   - `config_call_site_parity.assert_no_divergent_cfg_get_call_site_defaults`
   - `unresolved_imports.assert_all_from_imports_resolve`
   - `phantom_markdown_links.assert_no_phantom_markdown_links`
   - `pytest_markers.assert_markers_registered` (empty tests dir)

   Expected: a `min_files` floor, as in the other AST gates.

Behaviour judged by design, not recorded as a defect:
- `ci_workflow_gate` scans lines, so it passes malformed YAML.
- `source_text_claims` and `spec_bound_doubles` use a text prefilter that skips a broken file which cannot contain the shape. A broken candidate file does fail them.
- `entry_points_resolvable` raises a bare `TOMLDecodeError` without the path. It surfaces the problem, but it is less actionable.
