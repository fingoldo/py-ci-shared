# Wiring of the n1/n2 gates

## Wiring notes

- Registry: `registry.toml` gains `atomic_write_staging`, `clock_day_boundary`, `coverage_config_parity`, `hash_key_determinism`,
  `no_xfail_to_defer`, `numba_seed_range`, `pickle_state_completeness` (`assert_no_pickle_state_gaps`, `assert_pickle_round_trips`),
  `plotly_annotation_loop`, `polars_null_equality`, `pytest_addopts_path_runs`, `reiterated_iterable_params`, `rollback_then_continue`,
  `sentinel_or_fallback`, `stale_source_citations`, `stdlib_json_ban` (all `since = "1.17.0"`) and `resource_leak_guard` as a `library`
  (a pytest plugin with no `assert_*`). `import_cycles`, `local_copy_report` and `swallowed_exceptions` were already registered;
  `_gate_run` and `_gate_report` stay in `INTERNAL_MODULES`. The README catalogue is re-rendered from the registry.
- `resource_leak_guard` is loaded by `pytest_plugin.pytest_configure` through `pluginmanager.import_plugin` when
  `[tool.py_ci_shared] resource_leak_guard = true` (a non-bool is a `ConfigError`); it is not a `pytest11` entry point. Registered
  late, its historic `pytest_addoption`/`pytest_configure` are replayed, and pytest validates ini keys only after collection.
  Tests: `tests/test_pytest_plugin.py::test_the_table_loads_the_resource_leak_guard_only_when_asked` (off, on, and `-p` plus the table
  reporting once) and `::test_a_non_boolean_resource_leak_guard_is_a_usage_error`.
- Gate teeth: canaries for the six n2 AST gates (`polars_null_equality` run with `advisory=False`) and new canary dirs for the seven
  n1 AST gates without one (`atomic_write_staging`, `clock_day_boundary`, `hash_key_determinism`, `no_xfail_to_defer`,
  `sentinel_or_fallback`, `stale_source_citations`, `pickle_state_completeness`), generated by the scratchpad `gen_canary_n1.py`.
  `resource_leak_guard` is EXEMPT (runtime plugin); `coverage_config_parity` and `pytest_addopts_path_runs` keep their EXEMPT entries
  (they read `[tool.coverage]`/addopts against workflow and hook commands, CI configuration, not a file corpus).
- Markers: `integration`, `leak_guard_allow` and `no_leak_guard` appear only inside the fixture repos those tests write, so
  `tests/test_pytest_addopts_path_runs.py` and `tests/test_resource_leak_guard.py` join the existing `pytest_markers` exclude list
  instead of registering markers this repo never uses.
- `sys.path.insert` removed from the eleven new test files that carried it; `_SRC_INSERT_PENDING` is empty.
- `HARNESS_VERSION` 11 -> 12: `_mutation_fingerprint.fingerprint` now walks test dirs through `iter_files(..., exclude=DEFAULT_EXCLUDE)`,
  which changes which files a fingerprint covers, so cached mutation results keyed on it must not be reused;
  `tests/_mutation_harness_version_baseline.json` re-pinned by the gate's own bump path.
- `_core/config.load_config` split (`_gate_runs`, `_bool_key`) to stay under the C901 threshold after the new key.
